# ❓ How To's

The Todo of each stage teaches you **one** stage. A How To takes a question you'd have at work and follows it through **every** stage it touches, because real problems rarely stay inside one.

| ❓ How to… | 🗺️ Stages it touches | You'll learn what work calls… |
|---|---|---|
| [**add my own classes?**](add-my-own-classes.md) | 📷 1 → every stage | data collection, data leakage, grouped splits |
| [**train our model on cows?**](train-our-model-on-cows.md) | 🌳 6 → back to the stage at fault → 🌳 6 | error analysis, shortcut learning, ablation, domain shift |
| [**pick which model I am training?**](pick-which-model-i-am-training.md) | 🧬 5 → 🌳 6 · 🧠 6 → 🎤 7 | model selection, baselines, latency and size budgets |
| [**export a tflite file from our pipeline?**](export-a-tflite-file.md) | 🧠 6 → your app | edge deployment, quantization, training–serving skew |

Every How To has the same parts:

- 🎯 **Goal** · 🗺️ **Route** · 🧰 **You need**: what you'll have at the end, which stages you'll pass through, and what to have ready
- 🪜 **Steps**: checkboxes, in order
- 🔀 **If you see…**: what the pipeline might show you, what it means, and where to go next
- 🏆 **Done when**: a result you can measure or say out loud
- 💼 **At work this is called…**: the words to use in a job interview

Missing a question? Add a How To in this folder, in the same shape, and link it in the table above.
